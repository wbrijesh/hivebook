= Frontend · Data Fetching
:status: draft
:last-reviewed: 2026-06-10

All server state flows through the generated Connect client and TanStack Query.
No component calls `fetch`, builds a URL, attaches a token, or holds loading
state by hand.

[NOTE]
====
The API contract is proto-first over Connect
(xref:ROOT:design-docs/0006-api-transport-and-contract.adoc[design-doc 0006]).
The client below is *generated*, not hand-written. Until the generated clients
land, the single interim fetch layer is `lib/tenant.ts` — build new data paths
toward this target, and do not add a second hand-rolled `fetch` layer.
====

== Rules

. *One API layer — the generated client.* Every call to the Go API goes through
the Connect client generated from the proto (`web/lib/gen/...`). The client owns
the URL, the bearer token (via an interceptor that reads `lib/auth.ts`), and the
wire format. Nothing else calls the API directly.
. *TanStack Query owns server state.* Components read and write through
`@connectrpc/connect-query` hooks (`useQuery`, `useMutation`) bound to generated
service methods. Caching, loading, error, and refetch are Query's job — never a
hand-rolled `useEffect` + `useState` fetch.
. *Query keys come from the method.* Connect-Query derives a stable key from the
service method and the request message; a mutation invalidates the keys it
affects. Don't invent ad-hoc key strings.
. *One QueryClient at the root.* A single `QueryClientProvider` in the root
layout; defaults (`staleTime`, `retry`) are set once there.
. *Errors are `ConnectError`; Query surfaces them.* The transport throws a typed
`ConnectError` (with a `Code`) on failure; components render Query's `error`, not
their own `try/catch`. Field validation comes from protovalidate on the proto
(xref:ROOT:design-docs/0006-api-transport-and-contract.adoc[0006]).
. *Only the API layer knows the API* — base URL (`NEXT_PUBLIC_API_BASE`), the
bearer token, and the error model live in the client/interceptor, not at call
sites. Swapping transport or auth touches one layer.

== Shape

[source,tsx]
----
// lib/api/client.ts — the transport: one client, token via interceptor
const authInterceptor: Interceptor = (next) => async (req) => {
  const token = await accessToken()        // from lib/auth.ts
  if (token) req.header.set("Authorization", `Bearer ${token}`)
  return next(req)
}
export const transport = createConnectTransport({
  baseUrl: process.env.NEXT_PUBLIC_API_BASE!,
  interceptors: [authInterceptor],
})

// a component — usage only, hooks generated from the proto by connect-query
const { data, isPending, error } = useQuery(getTenant)
const onboard = useMutation(completeOnboarding, {
  onSuccess: () => queryClient.invalidateQueries(),
})
----

== Boundaries

* *Fire-and-forget telemetry is not server state.* `track()`
(xref:ROOT:standards/frontend/state-management.adoc[]) posts a beacon to
`/events` and never reads back — it stays a direct call, not a query, and is not
part of the Connect surface.
* *Auth stays in `lib/auth.ts`.* The transport interceptor pulls the access token
from the OIDC `userManager`; it does not own the session.
