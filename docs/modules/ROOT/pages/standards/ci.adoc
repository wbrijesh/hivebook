= Checks & CI
:status: living
:last-reviewed: 2026-06-12

One gate, one definition, run the same way everywhere. The checks are *code*
(a Dagger module in `.dagger/`), not shell scripts or CI YAML — so they run
identically on a laptop and in CI, in clean pinned containers.

== The gate

[source,bash]
----
just check        # the gate — what CI runs
dagger call check # the same thing, directly
----

`check` runs three suites in parallel, each in its own container:

* *proto* — `buf lint`, `buf format`, and a generated-code drift check
(regenerate from the proto and diff against the committed `gen/`, so a stale
commit fails). The contract is proto-first
(xref:ROOT:design-docs/0006-api-transport-and-contract.adoc[design-doc 0006]).
* *web* — `prettier --check`, `eslint`, `tsc --noEmit` (Node, pnpm).
* *api* — `go build`, `go vet`, and the *full* `go test ./...`, including the
testcontainers integration tests (a Docker-in-Docker engine is bound for them).

Toolchain images are pinned to match the service Dockerfiles, so the checks and
the shipped images agree on versions.

Breaking-change detection (`buf breaking`) needs git history, which the hermetic
Dagger context deliberately excludes — so it runs as its own job in
`.github/workflows/ci.yml`, against the PR base, not in the module.

== Where it lives

* `.dagger/main.go` — the pipeline. Add or change a check here, in Go.
* `dagger.json` — module + pinned engine version.
* `.github/workflows/ci.yml` — installs Dagger and runs `dagger call check`,
plus the one `buf breaking` job that needs git history. Otherwise all logic is in
the module, not the YAML.

The generated SDK bindings (`.dagger/internal`, `dagger.gen.go`) are gitignored
and regenerated automatically by `dagger call` / `dagger develop`.

== Local use

* `just check` before pushing — it is the same pipeline as CI.
* `just format` fixes web formatting (Prettier). The containerized equivalent is
`dagger call format export --path=web`.
* The only local tools the gate needs are `dagger` and a container engine
(OrbStack) — not Go, Node, or pnpm; those run inside the containers
(xref:ROOT:operations/infrastructure.adoc[prerequisites]).

== Adding a check

Add an exported method to the `Hivebook` type in `.dagger/main.go` and, if it
should gate merges, call it from `Check`. Functions are invocable immediately as
`dagger call <name>` (CamelCase → kebab-case). No SDK or YAML changes needed.
