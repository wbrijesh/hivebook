= Go · Testing
:status: living
:last-reviewed: 2026-06-06

Standard `testing`, real dependencies over mocks.

== Rules

. *Standard library `testing`*, `_test.go` beside the code it tests, functions
named `TestXxx`.
. *HTTP handlers use `net/http/httptest`* (see `internal/server/routes_test.go`).
. *Anything touching Postgres uses a real container via `testcontainers-go`* —
no hand-rolled DB mocks. Start the container once per package in `TestMain` and
share it (see `internal/database/database_test.go`).
. *`testify` is available* for assertions; plain `t.Fatalf` / `t.Errorf` is fine
for small tests — match the file you're in.
. *Table-driven tests* when a function has several input cases.
. *Migrations are tested both ways* — up applies the schema, up→down→up proves the
down files, a second up is a no-op (see `internal/database/migrate_test.go`).
. *Handlers depend on small interfaces* (the DB `Service`, the auth resolver) so
handler tests assert the HTTP contract — status codes, JSON, error mapping — with
stubs; query behavior is verified separately against a real container.
. *Run `go test ./...`* from `api/`; or `just check` to run it (and the web checks)
in containers, the same as CI. Tests pass before a change lands.
