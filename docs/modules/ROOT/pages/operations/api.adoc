= Hivebook API

The Go API (chi router, pgx/Postgres). Verifies ZITADEL JWT access tokens and
resolves the caller's identity and tenant server-side
(xref:ROOT:design-docs/0005-tenancy-and-onboarding.adoc[design-doc 0005]).

== Endpoints

* *Public:* `/health`, `/metrics`, `POST /events` (browser telemetry beacon).
* *Protected* (require a valid ZITADEL access token):
** `GET /api/me` — the session: caller identity + tenant.
** `GET /api/tenant` — the tenant and onboarding status (row created lazily).
** `POST /api/tenant/onboarding` — record onboarding answers; idempotent, region
write-once.

Schema migrations are embedded and applied on startup via golang-migrate
(xref:ROOT:adrs/0017-schema-migrations-golang-migrate.adoc[ADR-0017]); queries are
generated from SQL by sqlc (xref:ROOT:adrs/0018-sqlc-query-package.adoc[ADR-0018],
regenerate with `just gen`). See xref:ROOT:standards/go/database.adoc[database access].

[NOTE]
====
The transport is moving to Connect (proto-first)
(xref:ROOT:design-docs/0006-api-transport-and-contract.adoc[design-doc 0006]).
These REST routes are the current surface.
====

== Build / deploy / test

After a code change, rebuild the image and roll it out from the repo root:

[source,bash]
----
just update api      # rebuild hivebook-api:dev + zero-downtime rollout
----

Tests run in a container via the check gate — no local Go needed:

[source,bash]
----
just check        # web + api checks (build, vet, full test) via Dagger
----

If you happen to have Go installed, `cd api && go test ./...` works too (the DB
tests need Docker/OrbStack for testcontainers), but the gate is the source of truth.
