= Connector Catalog

Planned and considered connectors, with rough priority. This file
is the working catalog — not a roadmap commitment.

== v0.1 candidate set

The smallest set that meaningfully covers "`where decisions get
made, where they get written, where work gets tracked.`" Final v0.1
list chosen by design doc before build.

* *Slack* — primary comms surface, where most tribal knowledge
moves in real time
* *Google Workspace* — Drive {plus} Gmail; primary doc and email
surface for most mid-market companies
* *Notion* _or_ *Confluence* — pick one based on the first few
design partners’ choice
* *GitHub* — code, PRs, issues; high signal for engineering
knowledge
* One ticketing tool — *Jira* or *Linear* depending on design
partners

Plus, considered for v0.1 if a design partner needs it:

* A meeting recording source — *Gong*, *Granola*, or
*Fireflies* — because a large fraction of operational knowledge
lives in calls and this is a meaningful differentiator vs.
doc-only competitors

== Connector classes

* *First-party deep* — hand-built, deep semantic understanding
(e.g., Slack thread reconstruction, GitHub PR graph). Reserved
for the top 5–10 highest-value sources.
* *Provider-mediated* — built on a unified API provider (Nango,
Paragon, Merge). Used for the long tail.

The build-vs-integrate split itself is an open question — see
xref:ROOT:architecture/ingestion.adoc[].
