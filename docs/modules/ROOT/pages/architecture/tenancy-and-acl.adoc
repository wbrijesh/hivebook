= Tenancy and Access Control
:status: living
:last-reviewed: 2026-06-06

Access is enforced at two levels: across customers (strict isolation)
and within a customer (admin-managed, chapter-level).

== Across customers: strict isolation

* Every artifact, summary, embedding, entity, and audit record is
tagged with a `tenant++_++id`.
* Every read path filters by `tenant++_++id` before any other filter.
* No cross-tenant learning, signal sharing, or shared structure without
explicit opt-in. No such opt-in exists in v0.1. (xref:ROOT:adrs/0010-day-zero-enterprise-primitives.adoc[ADR-0010].)

== Within a customer: admin-managed chapter access

Access is granted at the chapter level. A user either has access to a
chapter or does not; within a chapter they see all topics and
sub-topics. Hivebook does not inherit or propagate source-system ACLs
(xref:ROOT:adrs/0009-chapter-level-access.adoc[ADR-0009]).

=== Default

Every member of the organization sees every chapter. The brain is a
shared organizational asset.

=== Admin chapter restrictions

Admins can narrow access for specific users or groups to a subset of
chapters. There is no per-topic or per-sub-topic access control.

=== Access templates

Admins define *access templates* representing personas, departments, or
roles (e.g., "Engineering", "Customer Support"). A template declares
chapter access; applying it to a user grants that access. Multiple
templates union.

Templates are authored after some ingestion has occurred — at
onboarding the book has no chapters to restrict.

== Identity

User identity comes from the tenant's SSO provider via the auth layer
(see xref:ROOT:architecture/enterprise-controls.adoc[]). There is no per-source identity
mapping — a consequence of not using source ACLs. The auth provider
build-vs-buy choice (Zitadel, WorkOS, hand-built) is deferred to build
time.

== Query-time enforcement

Every query path applies the requesting user's chapter access set,
filtering out sub-topics, topics, and raw-artifact spans outside their
accessible chapters, post-retrieval.

== Residency

Region is selected at the tenant level. Hosted tenants pick a region
cluster at onboarding; self-hosted tenants deploy in any region. See
xref:ROOT:architecture/enterprise-controls.adoc[].

== Audit

Every read and every privileged write is recorded to a per-tenant audit
log. See xref:ROOT:architecture/enterprise-controls.adoc[].
